# SHA-256

**SHA-256** é uma função de hash criptográfico da família SHA-2. Ela recebe uma entrada de qualquer tamanho e produz uma saída fixa de 256 bits.

O resultado normalmente é apresentado como 32 bytes ou 64 caracteres hexadecimais. A mesma entrada sempre produz o mesmo hash, mas é impraticável recuperar a entrada original apenas a partir do hash.

## Uma analogia

Imagine uma máquina que transforma qualquer documento em um código de identificação:

- documentos iguais produzem o mesmo código;
- uma pequena alteração produz um código completamente diferente;
- o código é curto e tem tamanho fixo;
- olhar apenas o código não permite reconstruir facilmente o documento.

Esse código é como uma impressão digital do conteúdo. Ele ajuda a comparar e detectar alterações, mas não é uma cópia escondida que possa ser “descriptografada”.

## Como o resultado é formado

SHA-256 sempre produz:

- **256 bits**;
- **32 bytes**;
- **64 caracteres hexadecimais**, quando representado em hexadecimal.

Exemplo conceitual:

```text
entrada: Olá
hash:    5ab... (64 caracteres hexadecimais)
```

O valor exato depende dos bytes da entrada. Texto com acento, espaços ou uma quebra de linha diferente produz outro resultado.

## Propriedades importantes

### Determinismo

Executar SHA-256 duas vezes sobre exatamente os mesmos bytes produz o mesmo resultado.

### Efeito avalanche

Uma mudança pequena na entrada, como trocar uma letra, costuma mudar muitos bits da saída. Isso dificulta identificar a entrada observando somente o hash.

### Via única (*one-way*)

Não existe uma operação prática de “desfazer” SHA-256 e recuperar qualquer entrada original. Ainda assim, entradas pequenas ou previsíveis podem ser descobertas por tentativa e comparação.

### Resistência a colisões

Uma colisão acontece quando duas entradas diferentes produzem o mesmo hash. Colisões são matematicamente possíveis porque existem infinitas entradas e um número finito de saídas, mas encontrar uma colisão prática em SHA-256 deve ser computacionalmente inviável quando o algoritmo é usado corretamente.

Isso não significa que qualquer uso de SHA-256 seja automaticamente seguro. O contexto, o protocolo, as chaves e a forma de armazenar o resultado também importam.

## SHA-256 não é criptografia

SHA-256 é hash, não criptografia:

| Hash | Criptografia |
| --- | --- |
| produz uma impressão de tamanho fixo | transforma dados em conteúdo que pode ser recuperado com uma chave |
| não tem descriptografia | possui operação de descriptografia |
| usado para integridade e comparação | usada para manter sigilo |
| SHA-256 é um exemplo | AES é um exemplo |

Também não é Base64. Base64 apenas representa bytes usando caracteres de texto e pode ser revertido facilmente. Ele não protege segredo nem impede leitura.

## Verificar a integridade de um arquivo

Se uma fonte confiável publica o hash de um arquivo, você pode calcular o hash local e comparar os valores.

No macOS:

```bash
shasum -a 256 arquivo.zip
```

Em muitas distribuições Linux:

```bash
sha256sum arquivo.zip
```

No [[PowerShell]]:

```powershell
Get-FileHash .\arquivo.zip -Algorithm SHA256
```

Se o resultado for diferente, o arquivo não é idêntico ao original. Isso pode acontecer por corrupção, versão diferente ou alteração maliciosa.

O hash precisa ser obtido de uma fonte confiável. Se um invasor substituir o arquivo e também substituir o hash publicado no mesmo local, a comparação sozinha não ajudará.

## Hash de texto

Para evitar adicionar uma quebra de linha acidental no macOS ou Linux:

```bash
printf 'mensagem' | shasum -a 256
```

Usar `echo` pode incluir uma quebra de linha dependendo do shell e das opções. O conteúdo exato dos bytes deve ser definido antes da comparação.

## Senhas

Não use SHA-256 puro para armazenar senhas. Senhas costumam ser curtas, reutilizadas ou previsíveis, e um atacante pode testar muitas possibilidades rapidamente.

Para senhas, use um algoritmo próprio e lento, como Argon2id, bcrypt ou PBKDF2, com salt único para cada senha. O sistema deve comparar o hash produzido pelo algoritmo de senha, sem guardar a senha original.

SHA-256 pode aparecer como parte interna de outras construções, mas não substitui um algoritmo de armazenamento de senhas. Veja as práticas de [[Segurança]].

## Integridade não é autenticidade

Um hash ajuda a detectar alterações quando você possui um valor confiável para comparação. Ele não prova sozinho quem criou o conteúdo.

Para autenticar uma mensagem, podem ser usados:

- **assinatura digital**: usa uma chave privada para assinar e uma chave pública para verificar;
- **HMAC**: combina um hash com uma chave secreta compartilhada;
- **TLS**: protege a comunicação e autentica o servidor durante a conexão.

Mesmo quando SHA-256 participa de uma assinatura, o hash sozinho não é a assinatura completa. As chaves, o algoritmo e a validação da cadeia de confiança também são necessários.

## SHA-256 no PKCE

No [[PKCE]], o método `S256` cria o `code_challenge` a partir do `code_verifier`:

```text
code_challenge = BASE64URL(SHA256(code_verifier))
```

Nesse caso, SHA-256 ajuda a enviar uma prova derivada sem enviar o segredo temporário no primeiro pedido. A codificação Base64 URL-safe transforma os bytes em texto adequado para uma URL; ela não é a proteção criptográfica.

## SHA-256 em JWT e TLS

Alguns nomes de algoritmos usam SHA-256 como parte do processo:

- `HS256`: HMAC usando SHA-256;
- `RS256`: RSA usando SHA-256;
- `ES256`: ECDSA com uma curva específica e SHA-256.

Esses nomes não significam que o payload de um [[JWT]] esteja escondido. O token pode continuar legível; a assinatura serve para verificar integridade e origem conforme a chave confiável.

No [[TLS]], hashes participam de verificações e da derivação de chaves, mas a proteção completa envolve negociação, certificados, troca de chaves e criptografia da sessão.

## Boas práticas

- use bibliotecas e ferramentas criptográficas mantidas;
- compare o hash no formato esperado e sobre os mesmos bytes;
- obtenha o hash de uma fonte confiável;
- use SHA-256 para integridade quando ele for adequado ao protocolo;
- não use SHA-256 puro para armazenar senhas;
- não confunda hash com criptografia ou Base64;
- não invente seu próprio algoritmo combinando hashes;
- proteja chaves secretas quando usar HMAC;
- valide assinaturas e certificados completos quando o objetivo for autenticidade;
- não coloque hashes de senhas, tokens ou dados sensíveis em logs sem necessidade.

**SHA-256 é uma função de hash que transforma dados em uma impressão digital de 256 bits, útil para verificar integridade e como componente de protocolos criptográficos.**
